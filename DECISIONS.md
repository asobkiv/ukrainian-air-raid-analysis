# Журнал рішень

## Погоджений обсяг

Користувач обрав волонтерське джерело як основне, київську північ, дві цілі — початки та години — й збереження авторських 30 хвилин. Загальні регіоно-години й грошові оцінки виключені. Лише ARIMA та експоненційне згладжування; прості орієнтири потрібні для чесного порівняння. Telegram перенесено після базової версії. Сезонність: один weekday-графік, ACF, таблиці та валідаційне порівняння; STL вилучено.

## Аудит джерела → вибір даних

Офіційний CSV оновлювався пізніше за останню дату подій. Не можна прирівнювати дату commit до актуальності історії. Волонтерський файл має 115989 рядків, останні події 11 жовтня 2026; 5812 умовних 30-хвилинних завершень належать авторам джерела. Дублікат визначається всіма полями, а не тривалістю чи днем місяця.

Проблема: завершений рядок і синтетичний finish можуть з'явитися після дати події. Сучасний CSV, просто обрізаний за started_at, давав би витік. Рішення: 100 Git-версій і консервативна доступність після успішного GitHub Actions run. Історичний active pickle потрібен лише для виявлення неготових міток; читається як дані без виконання коду.

Перевірка: SHA кожного CSV, відповідність workflow/parent, три незалежні replay-порівняння. Початкові історичні рядки доступні лише з першої замороженої версії; більш ранні origin не підтримуються.

## Агрегація → перевірка тривалості

Інтервали з naive=True збережено без виправлень. Час — об'єднання інтервалів в одному регіоні, а не сума з подвійним рахунком перетинів. Київські межі рахуються через UTC, щоб не припускати 24 години в кожній добі.

Відкрита подія без завершення є окремою ситуацією: не призначаємо їй 30 хвилин. Мітки від її початку цензуруються, поки завершення не доступне. Така консервативна політика може забирати частину вже відомих початків, але забезпечує однаковий набір днів для двох цілей та всіх моделей.

Перевірка: модульні тести плюс 40 незалежних sweep-line розрахунків стандартним datetime/csv, без використання виробничого об'єднання інтервалів.

## Покриття → обмеження формулювання

Сам CSV не має незалежного журналу повноти. Недавня активність джерела не доводить, що не було пропусків. Рішення: явно назвати ≥2 днів за 30 днів індикатором доступності, не «підтверджено повним покриттям». Луганщину та Закарпаття виключено; серед решти нуль — умовна відсутність записів. Це залишається обмеженням даних, а не розв'язаною статистичною задачею.

## Сезонність → моделі

Описова сезонність використовує тільки дані, доступні до першої валідації. ACF обчислено після вилучення лінійного тренду; поточкові межі не трактуються як формальне підтвердження за багатьох регіонів/лагів. Остаточний вибір сезонного варіанта — за MAE на попередніх origin, з RMSE як другим критерієм.

Фіксований компактний набір: ARIMA(1,0,1), сезонний AR(1) на лагу 7 як варіант ARIMA; SES і адитивне тижневе згладжування. Великий grid search не проводився. Модель годин навчається на частці доби, а метрики обчислюються в годинах.

## Допустимі значення → прозорий аудит

Користувач справедливо вказав на неможливість від'ємної кількості та частки поза [0,1]. Рішення: явне обмеження виходу, збереження raw, величини корекції та частоти. Вихід ARIMA не має природної підтримки лічильника. Дробовий прогноз є очікуваним значенням; округлення не додає точності. Для незбіжності — наперед визначене середнє 7 днів із причиною, ніколи мовчазний нуль.

## Протокол → фінальний тест

Перед виконанням зафіксовано config/protocol. Валідація 21 серпня — 10 вересня, тест 13 вересня — 10 жовтня. Мітки валідації взято з версії, опублікованої до тесту. Склад регіонів зафіксовано до тесту; придатність на кожному origin перевіряється лише за доступним минулим. Щоденне перенавчання дозволене, сімейство моделі після валідації не змінюється.

Затримка джерела означає фактичний горизонт 2–6 добових кроків, а не гарантовано один крок. Перевірка: журнал походження кожного прогнозу й тести, де майбутні рядки/знімки не змінюють минулих входів і прогнозу.

## Виправлена помилка під час перевірки

Перший запуск тесту виявив порівняння UTC origin з timezone-naive колонкою, що складалася лише з NaT. Виправлення: обидві колонки доступності нормалізуються через pd.to_datetime(..., utc=True) у as_of. Регресійні тести пройдено. Також явно задано старий tuple-формат результату ACF для statsmodels 0.15, щоб не залежати від зміни API за замовчуванням.

## Результат → наступні кроки

Macro MAE кількості: 2.0045 проти 2.2073, покращення 9.19%. Для годин: 1.4532 проти 1.4671, лише 0.95%. Поріг 5% виконано для першої цілі, не для другої. Тест не використовується для повторного налаштування. Нові моделі чи Telegram потребують нового майбутнього тесту або явно позначеного дослідницького порівняння з ризиком повторного використання вже відкритого тесту.
