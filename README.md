# Повітряні тривоги України: Python time series baseline

GitHub: [asobkiv/ukrainian-air-raid-analysis](https://github.com/asobkiv/ukrainian-air-raid-analysis). Репозиторій містить `.gitignore`, код, заморожені дані, виконаний notebook, результати та перевірки.

Щодня о **00:00 Europe/Kyiv** прогнозуємо добу **D, що починається в цей момент**: `[D 00:00, D+1 00:00)`.

Через затримку бачимо зазвичай дані лише за **D−2**. Тому це прогноз **на післязавтра відносно останньої готової доби**, у два кроки. Конкретний приклад із збережених прогнозів: **1 жовтня о 00:00** готові дані тільки за **29 вересня**; модель проходить 30 вересня як проміжний прогноз і прогнозує **1 жовтня, 00:00–24:00**. Відносно моменту запуску це найближчі 24 години. Незавершені інтервали іноді збільшують відстань до останньої готової доби до 6 кроків. [Часові межі кожного прогнозу](reports/forecast_timing.csv).

Дві цілі:

- кількість зареєстрованих початків тривог;
- години за записаними інтервалами тривог, через прогноз частки доби.

Дані: волонтерський файл [Vadimkin/ukrainian-air-raid-sirens-dataset](https://github.com/Vadimkin/ukrainian-air-raid-sirens-dataset). Заморожений SHA: `bf0c323c78e3e4508721458797dcd38c95df13f3`, доступний до `2026-10-11T04:50:19Z`. Історія подій починається 25 лютого 2022; 100 щоденних версій доступності відновлено з 4 липня 2026. Це версія проєкту з фіксованими даними; оновлення — окрема явна операція.

## Результат

Валідація: **21.08–10.09.2026**. Фінальний тест: **13.09–10.10.2026**, 23 допущені регіони, по 643 придатні регіональні доби на ціль.

Основне явне порівняння — з **mean_7 в усіх регіонах**: середнім семи останніх готових днів, доступних на момент прогнозу.

| Ціль | Macro MAE mean_7 | Macro MAE обраної моделі | Покращення | Поріг 5% проти mean_7 |
| --- | ---: | ---: | ---: | --- |
| Початки за добу | 2.0201 | 2.0045 | 0.77% | не виконано |
| Години за добу | 1.4973 | 1.4532 | 2.95% | не виконано |

Обрану модель визначено **окремо для регіону та цілі, тільки за валідацією**, серед ARIMA й експоненційного згладжування. Це не одна ARIMA для всіх регіонів. Результати тесту не використано для повторного підбору.

Попередні **9,19%** стосувалися іншого орієнтира: валідація вибрала `last` у 8 регіонах і `mean_7` у 15 для кількості. Тому 9,19% не є виграшем проти mean_7 в усіх регіонах. Для годин початковий орієнтир — `last` у 3, `mean_7` у 18, `weekly_naive` у 2; виграш проти нього 0,95%. Усі орієнтири тепер показано поруч у [таблиці порівняння](reports/baseline_comparison.csv), також є [окремі моделі ARIMA/SARIMA/SES/ETS](reports/test_macro_all_models.csv) і [порівняння за регіонами](reports/baseline_comparison_by_region.csv).

Явне порівняння з єдиним mean_7 додано після відкриття тесту за запитом користувача. Воно використовує вже збережені прогнози, без перенавчання чи зміни тесту. Початковий критерій і його результат збережені в `success_criteria.json`; додатковий — у `success_criteria_mean7.json`. Поріг 5% проти mean_7 не досягнуто для обох цілей.

## Встановлення

Перевірено на Python 3.12. Створіть окреме середовище; команди виконуйте з кореня цього проєкту.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock.txt
python -m pip install --no-deps --no-build-isolation -e .
```

Остання команда опціональна: `run.py` працює без встановлення пакета. Setuptools включено в зафіксовані залежності разом з інструментами для notebook і тестів. На іншій платформі wheel-версії можуть відрізнятися; перелік пакетів зафіксований, але це не гарантія побітової числової тотожності на всіх ОС.

## Відтворення замороженого експерименту

```bash
python run.py run --workers 4
python -m pytest -q
```

Перша команда перевіряє контрольні суми даних, формує добові ряди й сезонні артефакти, відтворює щоденні прогнози, обирає моделі на валідації, оцінює тест і будує звіт. Мережа для цього не потрібна. Збережений протокол захищає від випадкової зміни експерименту. Для нової конфігурації:

```bash
python run.py run --config config.json --output reports_new --workers 4
```

Порівняти два незалежні повторення й записати журнал перевірки:

```bash
python scripts/verify_reproduction.py reports reports_new
```

Паралельний запуск потребує кількох хвилин; `--workers 1` використовує один процес. Числові потоки BLAS за замовчуванням обмежено до одного на процес. Звіти й notebook читають дані з файлів, не потребують Telegram/API-ключів.

```bash
python run.py audit
python run.py report
python run.py forecast --date 2026-10-12 --workers 4
```

Прогноз містить SHA, origin, період навчання, реальний горизонт, сирий і обмежений вихід та причину резервного прогнозу. При джерелі старшому за 48 годин команда завершується помилкою. Для пізніших дат спочатку потрібне нове джерело й новий експеримент. Поточний прогноз: [selected.csv](reports/forecast_2026-10-12/selected.csv), 46 прогнозів моделей і 46 орієнтирів.

## Як влаштовано дані

- `data/volunteer_data_uk.csv.gz` — останній сирий CSV без редагування рядків.
- `data/event_ledger.csv.gz` — версії записів із `available_at` / `unavailable_at`.
- `data/snapshots.json` — SHA, GitHub Actions run, доступність, active-інтервали, останній оброблений ID.
- `data/workflow_runs.json`, `history_checks.json`, `provenance.json`, `checksums.json` — походження й перевірки.

Час початку події не є часом доступності рядка. Завершений CSV може з'явитися пізніше; навіть умовне завершення `naive=True` не робить його доступним заднім числом. Для кожного origin береться доступна Git-версія. Верхня межа публікації — завершення відповідного успішного workflow після push. Початкову історію консервативно вважаємо доступною тільки з першого збереженого snapshot.

`naive=True` означає **авторське правило 30 хвилин**, яке збережено без змін. Перетини в регіоні об'єднуються, тривалість доби враховує DST. Відкритий active-інтервал без завершення робить відповідні добові мітки неготовими; таку мітку не заповнюємо нулем і не включаємо в оцінку.

**Покриття:** недавня активність джерела — індикатор, а не незалежне підтвердження повноти реальних подій. Нуль означає відсутність записаних початків за припущенням про роботу джерела. 23 регіони допущено за правилом ≥2 різних днів із записами за попередні 30 днів; Луганську й Закарпатську області виключено. Крим відсутній у джерелі. Результат не можна називати прогнозом гарантовано всіх тривог України.

## Моделі та сезонність

До валідації: один зведений графік за днями тижня, ACF після вилучення лінійного тренду, таблиця відмінностей за регіоном/ціллю. STL не використовується.

Кандидати: ARIMA(1,0,1), тижнева SARIMA(1,0,1)×(1,0,0,7), SES та адитивне тижневе експоненційне згладжування без тренду. Орієнтири: останній доступний день, повтор тижня, середнє 7 днів. Навчальне вікно 180 днів, мінімум 60; через затримку даних фактичний горизонт може бути більше одного дня.

`last` повторює останній **готовий** день, який може бути позавчорашнім. `mean_7` використовує сім останніх готових добових значень, а не неготові календарні дні до запуску. Для часу усереднюється частка доби й множиться на довжину цільової доби 23/24/25 годин. На графіку прогнозів пунктиром показано саме `mean_7`.

Кількість обмежено знизу нулем; частку доби — [0,1], потім переведено в години цільової доби. Не округлюємо очікувану кількість перед метриками. Сирі прогнози збережено. Збій/незбіжність дає резервне середнє 7 доступних днів із записаною причиною. Прогнозні інтервали ще не оцінені.

## Перевірки й критерії успіху

Після кожного етапу є перевірки: SHA джерела; DST/північ/перетини; день тижня й узгодженість середніх; point-in-time replay; межі прогнозів; незалежні MAE/RMSE. Тести включають незмінність минулих входів і прогнозів після додавання майбутнього. [verification.json](reports/verification.json) містить підсумок чистого повторного запуску.

Незалежний Git-аудит трьох версій можливий за наявності checkout:

```bash
python run.py audit --repo /absolute/path/to/upstream
```

Репозиторій готовий, коли його можна встановити, відтворити заморожений експеримент і пройти тести з походженням кожного прогнозу. Звіт готовий, коли всі погоджені артефакти, обмеження й результати перевірок отримано з коду. Початковий критерій моделей — ≥5% зниження macro MAE проти вибраного на валідації орієнтира **для кожної цілі**. Додаткове явне порівняння проти mean_7 показує, що такого виграшу для жодної цілі немає. [Незалежний аудит орієнтирів](reports/baseline_comparison_audit.json) перевіряє однакові дати й перераховує помилки з прогнозів.

## Оновлення джерела

Оновлення не виконується під час звичайного повторного запуску. Для нової версії отримайте Git-історію та відповідні workflow runs. Наприклад:

```bash
git clone --depth 100 --single-branch --no-checkout https://github.com/Vadimkin/ukrainian-air-raid-sirens-dataset.git upstream
curl --fail --location 'https://api.github.com/repos/Vadimkin/ukrainian-air-raid-sirens-dataset/actions/workflows/update_datasets.yml/runs?per_page=100' --output workflow_runs.json
python run.py prepare --repo upstream --runs workflow_runs.json --data data_new
python run.py run --data data_new --output reports_new
```

Кількості commit/run повинні покривати один і той самий період; prepare зупиниться, якщо є непідтверджена відповідність. API GitHub може вимагати пагінації/автентифікації. Не зберігайте секрети в репозиторії. Активні інтервали з upstream pickle читаються вузьким інтерпретатором дозволених опкодів, без `pickle.loads` і виконання стороннього коду.
